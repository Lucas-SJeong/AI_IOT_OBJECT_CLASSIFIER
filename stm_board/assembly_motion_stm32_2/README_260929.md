## 핵심 변경

1. ESP 초기화 실패를 `Error_Handler()`로 보내지 않는다.
   - Wi-Fi/서버가 죽어도 버튼, Servo PWM, DHT11, LCD, RGB는 계속 동작한다.
2. 10초마다 실행하던 `AT+CIPSTATUS` / `AT+CIPSTART` 자동 재접속을 제거했다.
   - 메인 루프가 네트워크 명령 때문에 반복적으로 blocking 되는 현상을 제거한다.
   - 서버를 재시작한 경우 STM32 Reset 1회로 다시 연결한다.
3. 부팅마다 ESP에 `AT+RST`를 강제로 보내지 않는다.
   - 먼저 `AT`로 ESP 응답 여부만 확인한다.
4. `+IPD,<length>:payload`를 length 기준으로 별도 파싱한다.
   - 서버 명령 수신 버퍼와 AT 명령 응답을 분리한다.
5. Servo 상태를 `servoPulse` 하나로 통일했다.
   - 서버 `SERVO@각도` 후 버튼을 눌러도 이전 로컬 값으로 갑자기 점프하지 않는다.
6. PC0 버튼은 `Rising Edge + Internal Pull-down`이다.
   - 외부 저항 없이 `3.3V -- 버튼 -- PC0` 배선.
   - EXTI callback에 80ms debounce 적용.
7. DHT11 코드를 수정했다.
   - byte 변수 초기화 누락 수정.
   - response timeout 추가.
   - 무한 while 대기 방지.
   - checksum 검증 추가.
8. Reset cause를 UART에 출력한다.
   - `Reset cause : BOR/POR...`가 Servo 동작 때 반복되면 전원 강하를 우선 의심한다.

## IoT Server 실행 순서

Raspberry Pi:

```bash
pkill iot_server
cd /mnt/ubuntu_nfs/iot_socket
./iot_server 5000
```

그 다음 STM32 Reset.

정상 부팅 예:

```text
Start main() - wifi
Reset cause : ...
WiFi already connected : kcci603
ESP IP : 10.10.16.174
TCP connected : 10.10.16.77:5000
ESP/Server ready
```

서버가 꺼져 있으면:

```text
TCP connect fail(...)
ESP network init fail - local mode continues
```

이 경우에도 버튼/DHT/LCD/RGB는 계속 동작해야 한다. 서버를 다시 켠 후 STM32 Reset 1회.

## Server command

일반 iot_client에서:

```text
[SJH_ARD]SERVO@0
[SJH_ARD]SERVO@90
[SJH_ARD]SERVO@180
[SJH_ARD]RGB@50@0@0
[SJH_ARD]RGB@0@50@0
[SJH_ARD]RGB@0@0@50
[SJH_ARD]RGB@OFF
[SJH_ARD]LED@ON
[SJH_ARD]LED@OFF
```

- Servo 허용 값: `0~180`
- RGB 허용 값: 각 채널 `0~100`
- 잘못된 숫자/범위는 실행하지 않는다.

## 전원 주의

코드가 수정되어도 Servo 전원 문제는 소프트웨어로 해결할 수 없다.

Servo가 움직이는 순간 `Start main()`이 다시 출력되면서 `Reset cause : BOR` 또는 `POR/PDR`가 반복되면:

- Servo를 STM32 3.3V에서 구동하지 않는다.
- 가능하면 Servo용 안정적인 5V 전원을 별도로 사용한다.
- 외부 Servo 전원 GND와 Nucleo GND는 공통으로 연결한다.
- Servo Signal만 TIM4_CH1에 연결한다.

## 검토 상태

`esp.c`, `dht.c`, `main.c`, `clcd.c`는 STM32 HAL API용 stub을 사용해 C syntax / implicit declaration 검사를 통과시켰다.
실제 NUCLEO-F411RE + ESP8266 하드웨어 동작은 보드에서 Build/Upload 후 확인해야 한다.
